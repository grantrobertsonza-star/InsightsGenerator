# D2 design: dashboard configuration and generation (proposed, 29 October 2026)

Status: **proposed, not started.** Follows D1 (`claude/tracker-roles.md`). For Grant's review with Codex's
review of D1.

## Input to the recogniser

Per data file: the variable dictionary (names, labels, sets the reader found), value labels as the app already
resolves them (`resolveLabels` / `buildLabelOverlay` in `src/lib/labelOverlay.ts`: the data file's own labels,
then confirmed codebook and questionnaire entries by rank), and, where a confirmed codebook entry carries them,
the question ID, question type and multiple-response group. A file whose labels cannot be read gives
`unknown`, never an empty dashboard.

## Stored configuration (migration 0131, proposed)

`tracker_dashboards`: one row per project and programme (or per data file when the file is in no programme):
tenant, run, data document (the wave it was suggested from), `revision` (compare-and-swap on every save),
`suggested` (D1's output with the dictionary fingerprint and rule version it came from), `choices` (the
researcher's confirmations: focal brand, stage per question, non-brand codes, roles, hidden charts, segments),
`choices_by` / `choices_at`, `reset_at`. Suggested and chosen are kept apart, so Reset to suggested clears
`choices` and keeps a record; a new suggestion never overwrites a choice.

## New wave

When a newer wave's file is read, the configuration is carried by variable identity (names, then codes): a
chosen variable present in the new file is kept; one missing is shown as needing a choice, never dropped; a
role the new file adds is suggested, not applied. The dashboard says which wave its choices came from.

## Generation

The overview figures come from the existing owners: crosstab engine for funnel and attribute percentages
(unrounded, base stated), NPS and driver modules with the dashboard's filters, bases and weights. A module that
has not run or failed shows that state. No figure is computed in the dashboard layer.
